# config.yml reference

Exhaustive lookup table for a per-repo `config.yml`: every key, its type, whether it is required, its
source-verified default, and the complete catalogue of load-time rejections with exact error text.

Answers these questions:

- Where does the config file live, and what else does the factory read out of that folder?
- What is the minimum valid `config.yml`? What is the full key tree?
- What is the real default for `<key>` — and does a quoted number / `~` path work there?
- The load failed with `<message>`. What triggered it and how do I fix it?
- Which blocks reject unknown keys, and which silently swallow a typo?
- Which value wins when `agent` / `branch` / `budget_seconds` / a base prompt is set in two places?

Companions: work-source blocks in detail → [work-sources.md](./work-sources.md); step/belt semantics →
[belts-and-steps.md](./belts-and-steps.md); layout semantics → [layouts.md](./layouts.md); prompt
tokens → [prompts.md](./prompts.md).

## 1. Where config lives

| thing | path |
|---|---|
| config root | `$HERDR_FACTORY_CONFIG_DIR` (trimmed, if non-empty) else `~/.config/herdr-factory` |
| per-repo folder | `<configRoot>/repos/<repoName>/` |
| the config file | `<repoDir>/config.yml` — **required** |
| secrets | `<repoDir>/env` — `KEY=VALUE` lines, `#` comments and blanks skipped, first `=` splits, both sides trimmed. Written `chmod 600`. There is **no** global `<configRoot>/env` |
| repo guidance | `<repoDir>/guidelines-prompt.md` — optional; if present its whole text is appended to **every** step prompt of **every** belt as `## Repo-specific guidance` |
| prompt pack | `<repoDir>/prompts/<slug>.md` or `<repoDir>/prompts/<sourceType>/<slug>.md` — overrides the shipped base prompt for that step primitive |
| a step's `prompt_file` (`prompt_file_source: config`) | resolved relative to `<repoDir>`, or absolute |
| a belt's `match` predicate | a `.ts` file relative to `<repoDir>` (or absolute), `export default (ctx) => boolean` |
| editor JSON Schema | `<configRoot>/config.schema.json` (two levels up from the config.yml); `<configRoot>/machine.schema.json` for machine.yml |
| host-local machine limits | `<configRoot>/machine.yml` — optional, **not** per repo; gitignore it when the config dir is shared by git across hosts. See §3.14 |
| state (not config) | `$HERDR_FACTORY_STATE_ROOT` else `~/.local/state/herdr-factory`; one global db at `<state>/herdr-factory.db`, per-repo logs at `<state>/<repoName>/logs` |

**Repo name = folder name.** `herdr-factory --repo <name>` and every belt/run in the db key off the
directory basename under `repos/`. Repo discovery is `readdir(<configRoot>/repos)` keeping directories
that contain a `config.yml`, sorted — so a folder without a `config.yml` is invisible, and renaming the
folder renames the repo.

**Schema modeline — put this as line 1 of every config.yml:**

```yaml
# yaml-language-server: $schema=../../config.schema.json
```

The schema file is (re)generated by `herdr-factory schema` (add `--stdout` to print instead of write),
and also written automatically by `init`, `install`, and `serve` startup, so it tracks the installed
version. A stale schema produces bogus editor squiggles, never a load error. (Inside the factory repo
itself, `npm run schema` regenerates the committed `config.schema.json`; a test guards it against
drift.)

`prompt_file_source: repo` files and the `<worktree>/.herdr/prompts/` pack live in the **target repo's
worktree**, are read at render time, and therefore are never existence-checked at load.

**Load order** (`loadConfig`, `src/config.ts`) — useful because zod reports all issues at once but the
later steps abort on the first failure:

1. read + parse YAML + `RepoConfigSchema.safeParse` → all zod issues at once.
2. `expandHome(repo.path)`, then `assertMainCheckout`.
3. read `guidelines-prompt.md`.
4. resolve sources (name, poll interval, per-source cap, descriptor `resolveConfig`).
5. resolve belts → steps — where `match` / `prompt_file` existence + prompt-contract checks throw.
6. normalize layouts — where pane `size` throws.
7. stable-sort belts by `priority` ascending.

## 2. Skeleton

Minimum valid config (three required top-level blocks: `repo`, `work_sources`, `belt`):

```yaml
# yaml-language-server: $schema=../../config.schema.json
repo:
  path: ~/dev/acme
work_sources:
  - type: local_markdown
    local_markdown:
      folder: ~/briefs
belt:
  - name: briefs
    source: local_markdown
    steps:
      - type: work
      - type: pr
```

The per-type wrapper key is **always required**, even when empty (`github_issues: {}`). Omitting it
gives `work_sources.0.<type>: Invalid input: expected object, received undefined`.

Full key tree — `!` = required, everything else optional with the default shown:

```
repo!                     { path! , base_ref="origin/main" , github=<git origin> }
limits                    { max_active_workspaces=3 , attention_renotify_seconds=3600 , stall_seconds=2700 ,
                            max_bounces=6 , max_capture_attempts=5 , step_budget_seconds=3600 ,
                            tick_interval_seconds=60 , reconcile_concurrency=8 , max_claims_per_tick=10 ,
                            source_poll_interval_seconds=<unset> , layout_wait_seconds=600 }
work_sources![]           { type! , name=<type> , poll_interval_seconds , max_active_workspaces=2 ,
                            claim_guard { enabled=false , host=<hostname> , settle_ms=2000 } ,  # jira + github_issues only
                            <type>!: { … } }      # one wrapper block per type
belt![]                   { name! , source! , steps![] , priority=100 , active=true , label ,
                            workspace_name , match , max_bounces , default_layout , layout_matching=[] ,
                            pr , branch , agent , effects=[] }
  steps[]                 { type! , name=<type> , tab , pane , prompt_file , prompt_file_source="config" ,
                            prompt_mode="augment" , budget_seconds , heartbeat=false , agent ,
                            consumes , produces , read_only , bounce }   # last four: custom only
  effects[]               { on! , to! , anchor , step|product|outcome! }
  pr                      { draft , title , labels[] , reviewers[] , assignees[] , automated_round_minutes }
  layout_matching[]       { worktree_pattern! , layout! , title }
layouts[]=[]              { id! , tabs![] , setup , env={} }
  tabs[]                  { title , panes![] }
    panes[]               { title , command , persist=true , agent , agent_name , agent_args=[] ,
                            prompt , agent_timeout_ms , prompt_timeout_ms , env={} , setup=false ,
                            split , ratio , size }
evidence                  { publisher="s3" , key_prefix="" , github_username , …per-publisher }
conventions               { commits }
branch                    { prefixes , slug_max=20 , full_slug_max=50 }
agent                     { command="claude" , flags=[] , kind }
```

## 3. Per-block key reference

**Coercion rules that apply throughout:**

- Every numeric field **except the layout pane `ratio`/`size`** is `z.coerce.number().int()`, so a
  quoted YAML number works (`budget_seconds: "900"` is accepted). Pane `ratio`
  (`z.number().gt(0).lt(1)`) and a numeric pane `size` (`z.number().positive()`) are plain uncoerced
  numbers — write `ratio: 0.5` / `size: 40` unquoted; `ratio: "0.5"` gives
  `Invalid input: expected number, received string` and `size: "40"` gives
  `size must be a percentage like "30%"`.
- `active` is a **strict boolean** — `active: "false"` is **rejected**
  (`belt.0.active: Invalid input: expected boolean, received string`). Same for every other boolean.
- `~`, `~/…`, `$HOME`, `${HOME}` expansion (`expandHome`) applies to **only two keys**: `repo.path` and
  `local_markdown.folder`. It is **not** applied anywhere else. `match` / `prompt_file` are joined
  onto `<repoDir>`, so a `~/…` there fails the load with `… not found: <repoDir>/~/…`.
  `conventions.commits` is also joined onto `<repoDir>`, but a path that doesn't stat is silently used
  as literal prompt text (no error). Layout pane `command`s are passed verbatim to `herdr pane run`, so
  the pane's shell expands `~` normally; `evidence.command` is exec'd with no shell, so a leading `~`
  stays literal and the exec fails.

### 3.1 `repo` (required)

| key | type | req | default | meaning |
|---|---|---|---|---|
| `path` | string | **yes** | — | The project's **MAIN** (non-linked) checkout that clone worktrees fork from. `expandHome`d. |
| `base_ref` | string | no | `"origin/main"` | The ref worktrees branch from and PRs target. |
| `github` | string | no | derived from the checkout's git origin (`""` if unresolvable) | `owner/name` PRs are opened against. |

### 3.2 `limits`

Every field is defaulted (the whole block has `.prefault({})`, so omitting it is identical to
`limits: {}`).

| key | constraint | default | meaning |
|---|---|---|---|
| `max_active_workspaces` | positive | **3** | Repo-wide ceiling on claimed workspaces. |
| `attention_renotify_seconds` | positive | **3600** | Re-notify interval for an item still needing attention. |
| `stall_seconds` | positive | **2700** | Heartbeat / commit-stall window before a step is declared stalled. |
| `max_bounces` | **non-negative** (0 legal) | **6** | Bounces before escalation; per-belt override. |
| `max_capture_attempts` | **non-negative** (0 legal) | **5** | Evidence capture attempts before escalation. |
| `step_budget_seconds` | positive | **3600** | Last-resort step budget (only when the descriptor has no default). |
| `tick_interval_seconds` | positive | **60** | Reconcile tick period. |
| `reconcile_concurrency` | positive | **8** | Parallel run reconciliations per tick. |
| `max_claims_per_tick` | positive | **10** | New claims per tick. |
| `source_poll_interval_seconds` | positive | **no default** | Repo default poll interval; unset ⇒ `tick_interval_seconds`. |
| `layout_wait_seconds` | positive | **600** | How long a step waits for its layout pane before escalating. |

The shipped example config (`examples/example-repo/config.yml`) shows `max_bounces: 3` — that is a
sample value. **The schema default is 6.**
`develop_budget_seconds`, `evidence_budget_seconds`, `review_budget_seconds`, `pr_budget_seconds` were
removed; because `limits` is not strict they are now silently ignored. Use `steps[].budget_seconds`.

### 3.3 `work_sources[]` — common fields (required, `min(1)`)

Present on every source type:

| key | type | req | default |
|---|---|---|---|
| `type` | enum `jira` \| `local_markdown` \| `github_issues` \| `sentry` (discriminator) | **yes** | — |
| `name` | string trimmed min1 | no | **= `type`**; must be unique per repo |
| `poll_interval_seconds` | int positive | no | `limits.source_poll_interval_seconds` → `limits.tick_interval_seconds` |
| `max_active_workspaces` | int positive | no | **2** — per-source cap, summed across belts, under the repo ceiling |
| `claim_guard` | object, strict | no | unset (off). **`jira` and `github_issues` only** — rejected on `local_markdown`/`sentry`. `enabled` bool **false**; `host` matching `^[A-Za-z0-9._-]+$` (error: ``claim_guard.host` may only contain letters, digits, '.', '_' and '-'``), default = the machine hostname with other chars folded to `-`; `settle_ms` int ≥ 0, **2000**. Lets several factories with separate DBs share the source — see [work-sources.md](./work-sources.md#several-factories-on-one-source-claim_guard) |

Plus exactly one required wrapper block naming the type. Full key tables, credentials, eligibility and
write-backs are in [work-sources.md](./work-sources.md); the schema shape in one line each:

| block | required keys | notable defaults |
|---|---|---|
| `jira` | `base_url` (full URL), `project`, `board` (string or int → coerced to string) | `status.todo="To Do"`, `status.in_development="In Progress"`, **`status.review="In Review"`**, `status.done` unset; extra `status.<key>` = custom statuses |
| `github_issues` | *(none — `github_issues: {}` is valid)* | `state_labels.in_development="herdr:in-development"`, **`state_labels.in_review="herdr:in-review"`**, `state_labels.aborted="herdr:aborted"`, `close_on.merged=true`, `close_on.done=true`, `close_on.aborted=false`, `default_type="Feature"`, `max_pages=1` (1–10), `type_labels` = `{bug:Bug, defect:Bug, chore:Chore, task:Chore, enhancement:Feature}` and **setting it replaces the whole map** |
| `local_markdown` | `folder` (`expandHome`d) | — (not strict: unknown keys inside are dropped) |
| `sentry` | `organization` | `base_url="https://sentry.io"`, `projects=[]` (all), `environment=[]` (all), `query="is:unresolved"`, `stats_period="14d"`, `on_merge="comment"` |

`label` is required on a belt over `jira` / `github_issues` and forbidden on `local_markdown` /
`sentry` — see §6.3 rows 5–6.

### 3.4 `belt[]` (required, `min(1)`) — note the **singular key holding an array**

| key | type | req | default | meaning |
|---|---|---|---|---|
| `name` | string trimmed min1 | **yes** | — | Unique per repo; the identity in the db, TUI and logs. |
| `source` | string trimmed min1 | **yes** | — | A resolved `work_sources[].name`. |
| `steps` | array `min(1)` | **yes** | — | The ordered pipeline. |
| `priority` | int, **negatives allowed** | no | **100** | Lower = matched first at claim time. |
| `active` | boolean (strict) | no | **true** | `false` ⇒ no NEW claims; in-flight runs still progress. |
| `label` | string trimmed min1 | conditional | **no default — deliberate** | The pickup label/trigger label for label-driven sources. |
| `workspace_name` | template string | no | `"{{semantic_work_prefix}}/{{work_id}}-{{work_full_slug}}"` | Must contain `{{work_id}}`. Names the **worktree/workspace** (the run's identity, `runs.worktree_name`) and the branch it starts on; the branch can later be renamed by the agent (see below). |
| `match` | path to a `.ts` module | no | unset ⇒ the belt accepts anything from its source | `export default (ctx) => boolean`. |
| `max_bounces` | int non-negative | no | `limits.max_bounces` | |
| `default_layout` | a `layouts[].id` | no | unset ⇒ the factory builds no layout | Setting it turns on the step→pane allocation checks (§6.3 #10–10c) **and** obliges the belt's first *surviving* step to carry `tab`+`pane` (#10d). |
| `layout_matching` | array of rules | no | `[]` | |
| `pr` | strict object | no | unset | Prompt tokens only — see §3.6. |
| `branch` | strict object | no | falls back to top-level `branch`, then built-in | |
| `agent` | strict object | no | falls back to top-level `agent`, then `DEFAULT_AGENT_CONFIG` | |
| `effects` | array | no | `[]` | Status write-backs. |

`workspace_name` template vars: `{{work_id}}` (case preserved), `{{work_type}}` (lowercased),
`{{semantic_work_prefix}}`, `{{work_full_slug}}` (≤ `full_slug_max`), `{{work_slug}}` (≤ `slug_max`).
Unknown `{{vars}}` render empty. The rendered name is git-sanitised and a short per-claim uid is
appended, so a re-claim gets a distinct worktree.

**The branch is not the run's identity.** `workspace_name` names the worktree (frozen at claim, in
`runs.worktree_name`) and the branch it starts on. An agent may then move the run onto the name this
repo's branching/CI convention requires — a ticket key it only obtains mid-run, a mandated prefix —
with `herdr-factory --repo <name> set-branch <KEY> <branch>` (rendered into every step prompt as
`@@SET_BRANCH_CMD@@`; a bare `git branch -m` is followed too, on the next reconcile pass). The engine
then uses the new name for prompts, PR discovery, and teardown cleanup, and it deletes BOTH names at
teardown. The rename is refused for an invalid/colliding name, a **protected** branch (the `base_ref`
or the main checkout's branch), or once the run's PR is open. There is **no config key** for the
convention itself — say it in the belt's `prompt_file`, where the repo's own rules live.

`.strict()` here is what rejects the **removed** `belt_type:` and `agents:` keys, as
`Unrecognized key: "belt_type"`.

### 3.5 `belt[].steps[]`

| key | type | req | default | meaning |
|---|---|---|---|---|
| `type` | enum `work` \| `evidence` \| `review` \| `pr` \| `custom` | **yes** | — | The primitive. |
| `name` | trimmed, `/^[a-z0-9][a-z0-9_-]*$/` | no | **= `type`** | Unique within the belt. |
| `tab` | string | no | — | Layout tab title. Both-or-neither with `pane`. **Required on the first surviving step of a `default_layout` belt** (§6.3 #10d). |
| `pane` | string | no | — | Layout pane title; omit both to spawn a dedicated pane — legal on every step *except* that first one. |
| `prompt_file` | string | **yes for `custom`** | — | Relative to `<repoDir>` (source `config`) or to the worktree (source `repo`). |
| `prompt_file_source` | enum `config` \| `repo` | no | **`"config"`** | Inert (and dropped) without a `prompt_file`. |
| `prompt_mode` | enum `augment` \| `replace` | no | **`"augment"`** | Likewise inert without a `prompt_file`. |
| `budget_seconds` | int positive | no | the primitive's descriptor default → `limits.step_budget_seconds` | |
| `heartbeat` | boolean | no | **false** | Enables the commit-stall guard; implies producing commits. |
| `agent` | strict object | no | belt → repo → `DEFAULT_AGENT_CONFIG` | |
| `consumes` | `array(enum["commits"])` | no | — | **`custom` only.** |
| `produces` | `array(enum["commits"])` | no | — | **`custom` only.** |
| `read_only` | boolean | no | — | **`custom` only.** |
| `bounce` | boolean | no | — | **`custom` only.** |

Descriptor defaults that the schema defers to (semantics in [belts-and-steps.md](./belts-and-steps.md)):

| type | default `budget_seconds` | requires a layout pane? | bounces? |
|---|---|---|---|
| `work` | 5400 | no | no |
| `evidence` | 2400 | **yes — no `tab`+`pane` ⇒ the step is SILENTLY SKIPPED at load** | yes |
| `review` | 1800 | no | yes |
| `pr` | 3600 | no | no |
| `custom` | none ⇒ `limits.step_budget_seconds` | no | opt-in via `bounce` |

`consumes`/`produces`/`read_only`/`bounce` are legal only on `custom` because only that descriptor sets
`refCapabilities: true`. The product allow-list for them is **`commits` only** — `produces:
[pull_request]` fails at parse.

### 3.6 `belt[].pr` — delivered as **prompt tokens**, never applied engine-side

| key | type | default |
|---|---|---|
| `draft` | boolean | unset |
| `title` | template string (same vars as `workspace_name`, rendered **verbatim** — no git sanitisation) | unset |
| `labels` | `array(string min1)` | unset |
| `reviewers` | `array(string min1)` | unset |
| `assignees` | `array(string min1)` | unset |
| `automated_round_minutes` | int **non-negative** (0 = skip the CI/bot round entirely) | unset ⇒ the prompt's default (~10 min) |

Rendered into `@@PR_OPTIONS@@` / `@@PR_AUTOMATED_ROUND@@`; the agent still runs `gh pr create`.

### 3.7 `belt[].effects[]` — discriminated union on `on`

Common to all three members: `to` (string trimmed min1, **required**) and `anchor` (optional, one of
the six canonical `WORK_STATES`).

| `on` | extra required key | legal values |
|---|---|---|
| `enter` | `step` | any step **name** written in the belt |
| `produce` | `product` | **only** `evidence` \| `pull_request` |
| `teardown` | `outcome` | `merged` \| `closed` \| `abandoned` \| `timeout` \| `completed` |

**Only `merged`, `completed` and `abandoned` are ever written.** The `Outcome` type and this schema
accept all five, but no code path in `src/core/reconcile.ts` calls teardown with `closed` or `timeout`
— a `{ on: teardown, outcome: closed }` (or `timeout`) effect validates, loads clean, and can never
fire. Write the outcome you actually get: `merged` (PR merged), `completed` (last step done on a belt
with no PR watch), `abandoned` (manual `teardown`, stale-item abort, and the `run.outcome ?? "abandoned"`
fallbacks).

Rank/monotonicity: a canonical `to` ranks `todo`=0, `in_development`=1, `in_review`=2,
`merged`/`done`/`aborted`=3; a custom `to` ranks `anchor − 0.5` (it sits just before its anchor stage).
Effects fire forward-only — a rank lower than the highest already enqueued is a logged no-op. Engine
defaults that always exist: `enter <first step>` → `in_development`, `produce pull_request` →
`in_review`; a belt effect on the same trigger **replaces** the default.

### 3.8 `belt[].layout_matching[]`

| key | type | req | note |
|---|---|---|---|
| `worktree_pattern` | string trimmed min1 | **yes** | Glob: only `*` (any run of chars, **including `/`**) and `?` (one char) are special; anchored to the full string. |
| `layout` | string trimmed min1 | **yes** | Must be a defined `layouts[].id`. |
| `title` | string | no | **Documentation only** — parsed, then discarded. |

### 3.9 `layouts[]` (default `[]`) — schema only; semantics in [layouts.md](./layouts.md)

| key | type | req | default |
|---|---|---|---|
| `id` | string trimmed min1 | **yes** | — |
| `tabs` | array `min(1)` | **yes** | — |
| `setup` | strict `{ command, blocking }` | no | — |
| `setup.command` | string trimmed min1 | **yes** within `setup` | — |
| `setup.blocking` | boolean | no | **false** |
| `tabs[].title` | string trimmed min1 | no | untitled ⇒ **unaddressable** by a step's `tab` |
| `tabs[].panes` | array `min(1)` | **yes** | — |
| `panes[].title` | string trimmed min1 | no | untitled ⇒ **unaddressable** by a step's `pane` |
| `panes[].command` | string trimmed min1 | no | run as the pane's PROCESS in your interactive login shell (`sh -c 'exec "$SHELL" -lic …'`), not typed into it; mutually exclusive with `agent` |
| `panes[].persist` | boolean | no | **true** — hand the pane back to a prompt when `command` exits. Only valid with `command` |
| `panes[].agent` | enum: a herdr agent kind | no | this pane hosts that agent: `herdr agent start --kind --pane`, which blocks until herdr has DETECTED it and marked it ready for input. What a step-targeted pane should use; mutually exclusive with `command` |
| `panes[].agent_args` | `array(scalar)` → strings | no | `[]` — passed to the agent after `--` |
| `panes[].agent_name` | string matching `[a-z][a-z0-9_-]{0,31}` | no | herdr's agent alias (its own charset rule; unique among LIVE agents). Derived from kind + workspace when unset |
| `panes[].prompt` | string trimmed min1 | no | opening prompt submitted once the agent is ready. REJECTED on a pane a step targets (the step's prompt is dispatched there) |
| `panes[].agent_timeout_ms` | int > 0 | no | 60000 — readiness wait for `agent start` |
| `panes[].prompt_timeout_ms` | int > 0 | no | set ⇒ wait for the agent to settle (idle/done) after prompting; unset ⇒ submit and move on |
| `panes[].env` | map of scalars → strings | no | `{}` — the pane's environment; merged over the layout's `env` (pane wins) |
| `panes[].setup` | boolean | no | **false** — marks the pane that runs the layout-level `setup.command`; at most one per layout |
| `panes[].split` | enum `vertical` \| `horizontal` \| `right` \| `down` | no | ignored on pane 0; normalized `vertical`/`right`→`right`, `horizontal`/`down`→`down` |
| `panes[].ratio` | number `>0` and `<1` | no | **legacy** — the fraction the PREVIOUS pane keeps; mutually exclusive with `size` |
| `panes[].size` | `"<digits>%"` string \| number `>0` | no | `0<n<1` → that fraction as a percent; integer `≥1` → fixed cells |

### 3.10 `evidence` — discriminated union on `publisher`

A block with no `publisher:` key is treated as `publisher: s3`, so legacy blocks stay byte-identical.
Shared by all publishers:

| key | type | req | default | coercion |
|---|---|---|---|---|
| `key_prefix` | string | no | `""` | trimmed, then leading **and** trailing `/`s stripped |
| `github_username` | string trimmed min1 | no | the `gh` login at upload time | — |

| publisher | keys |
|---|---|
| `s3` | `bucket`**!**, `region`**!**, `cloudfront_domain`**!** (a `https?://` prefix and trailing `/`s are stripped to a bare host), `profile` (optional AWS CLI named profile) |
| `local` | `public_base_url` — default `http://127.0.0.1:<server port>`, trailing `/`s stripped |
| `command` | `command`**!** (`string` or non-empty `array(string)`; a bare string becomes a 1-element argv, run with **no shell**, capture dir + key prefix appended as the last two args), `timeout_seconds` (int positive, default **300**) |

Object key layout is publisher-independent:
`herdr-factory/<github_username>/<key_prefix>/<work_key>/<runId>-<stamp>/<file>`, empty segments
dropped. AWS credentials come from the ambient chain — never from config.

### 3.11 `conventions`

| key | type | req | meaning |
|---|---|---|---|
| `commits` | string trimmed min1 | no | Short free text **or a file pointer** (absolute, or relative to `<repoDir>`). Resolved at render time, best-effort: if the path stats as a file its contents are used, otherwise the value is literal text. Surfaces as `@@COMMIT_CONVENTIONS@@`; unset ⇒ the token renders empty. |

### 3.12 `branch` (top-level and per-belt)

| key | type | default |
|---|---|---|
| `prefixes` | `record(string→string)` | built-in `{ bug: "fix", defect: "fix", chore: "chore", task: "chore" }` |
| `slug_max` | int positive | **20** |
| `full_slug_max` | int positive | **50** |

`prefixes` has a **reserved `default` key** split out as the fallback prefix; omitted ⇒ `"feature"`. A
work type matches a `prefixes` key **case-insensitively by substring**, keys tried in declaration
order, first match wins (so a type `"Dev bug"` matches the `bug` rule).

### 3.13 `agent` (top-level, per-belt, per-step)

| key | type | default once any block is set |
|---|---|---|
| `command` | string trimmed min1 | `"claude"` |
| `flags` | `array(string)` (elements may be empty strings) | `[]` |
| `kind` | enum — a herdr agent kind (`claude`, `codex`, `opencode`, `gemini`, `cursor`, `pi`, `copilot`, `droid`, `amp`, … — the `herdr agent start --kind` set) | *unset* |

No block anywhere ⇒ `DEFAULT_AGENT_CONFIG` = `{ command: "claude", flags:
["--dangerously-skip-permissions"] }`. Spawned argv is `[command, ...flags, prompt]`.

The factory creates the pane and asks herdr to **adopt** the harness into it (`agent start --kind
--pane`), which blocks until the agent is ready for input. The kind is derived from `command`'s basename
when that is a bare, known name; `kind:` is for the cases it can't be — a wrapper script or an absolute
path — and without it such a `command` is merely typed into the pane (no readiness handshake, herdr's
own process detection only).

This resolution drives the panes the factory **spawns**. A LAYOUT pane names its own agent (`agent:`
kind + `agent_args`), so the layout owns the harness for the panes it builds.

### 3.14 `machine.yml` (host-local, optional — `src/machine.ts`)

A separate file at `<configRoot>/machine.yml`, strict (unknown keys rejected). Absent file, empty file,
or absent key = no machine gate (byte-identical to not having the feature).

| key | constraint | default | meaning |
|---|---|---|---|
| `max_active_workspaces` | int ≥ 0 | unset | Ceiling on **occupying** runs across ALL repos in the shared DB (same posture as the repo cap: parked / `waiting_for_human` / idle PR-watch hold no slot). `0` ⇒ this host claims nothing new. Also enforced on manual `claim` |
| `min_free_memory_mb` | int ≥ 0 | unset | Skip Phase B claims while available memory is below it. Linux `MemAvailable`; macOS `vm_stat` free + inactive + speculative; else `os.freemem()` |

Errors: `invalid machine config (<path>):\n  <key>: <zod message>` — from `doctor` (row `machine limits
(machine.yml)` ✗), every `--repo` command, and `serve` cold start (every repo fails to load). A hot
`reload` with an invalid file is refused whole (`⚠ machine.yml: not reloaded: …`) and the running limits
stay. `reload` otherwise picks up edits.

## 5. Precedence and resolution

**`agent` — whole-block, most-specific-wins, NOT field-merged.** `step.agent ?? belt.agent ??
repo.agent`; the first block found wins **entirely**, and within it `command` defaults to `"claude"` and
`flags` to `[]`. A belt setting `agent: { command: codex }` over a repo-level `flags: [--sandbox]`
resolves to `{ command: "codex", flags: [] }` — it does **not** inherit `--sandbox`. Repeat the flags in
the more specific block if you want them.

**`branch` — per field, but `prefixes` replaces wholesale.** `prefixes` = `belt ?? repo ?? built-in`
(a set map never merges with the built-in). `slug_max` and `full_slug_max` each resolve
`belt ?? repo ?? 20/50` independently.

**`max_bounces`**: `belt.max_bounces ?? limits.max_bounces`.

**Step budget**: `step.budget_seconds ?? descriptor default ?? limits.step_budget_seconds`.

**Poll interval**: `source.poll_interval_seconds ?? limits.source_poll_interval_seconds ??
limits.tick_interval_seconds`. A value at or below the tick interval is a no-op — a source cannot be
polled faster than the tick fires.

**Per-source concurrency**: `source.max_active_workspaces ?? 2`, with
`limits.max_active_workspaces` as the repo-wide ceiling.

**Base prompt chain** (highest first): `<worktree>/.herdr/prompts/` → `<repoDir>/prompts/` → shipped
`src/prompts/`; within a pack `<dir>/<sourceType>/<slug>.md` beats `<dir>/<slug>.md`. The winner is then
augmented (or replaced) by the step's `prompt_file`. Details in [prompts.md](./prompts.md).

**Layout selection per worktree**: walk `belt.layout_matching` in **written order**, first rule whose
glob matches and whose layout exists wins; else `belt.default_layout`; else nothing is built. See
[layouts.md](./layouts.md).

**Belt claim order**: belts are stable-sorted by `priority` ascending (ties keep config order); at claim
time the first belt whose `match` accepts an item wins.

**Derived, never written**: whether the factory watches a PR (some step produces `pull_request`), and
the display-only belt type label.

### 6.4 Load-time throws (plain errors — these abort on the FIRST failure)

| trigger | exact message | fix |
|---|---|---|
| no config.yml | `no config for repo "<name>" at <ymlPath>` | Create the folder + `config.yml`, or run `herdr-factory init` inside the checkout. |
| any zod failure | `` invalid config for repo "<name>" (<ymlPath>):\n  <path>: <msg>… `` — one indented `  <dotted.path>: <message>` line per issue (`(root)` when the path is empty) | Fix each listed path. |
| `repo.path` has no `.git` | `repo.path "<p>" is not a git checkout (no .git)` | Point at the checkout root. |
| `repo.path` is a linked worktree | `repo.path "<p>" looks like a linked worktree (.git is a file); herdr needs the MAIN checkout` | Point at the main clone — herdr cannot fork worktrees from a worktree. |
| a belt's `match` file is missing | `belt "<belt>": match not found: <abs>` | Create the `.ts` file at that path (relative paths resolve against `<repoDir>`, and `~` does **not** expand here). |
| a `config`-sourced `prompt_file` is missing | `belt "<belt>": step "<name>" prompt_file not found: <abs>` | Same. |
| a `config`-sourced `prompt_file` breaks the prompt contract | `` belt "<belt>" step "<name>" prompt_file (<abs>) violates the prompt contract:\n  - <problem>\n  - …\n(see docs/PROMPTS.md for the token reference) `` | Fix each listed problem — see below. |
| pane `size` out of range | `layout "<id>": size "<raw>" must be a percentage between 0% and 100%` | Use 1–100%. |
| pane `size` a non-integer ≥1 | `layout "<id>": a fixed pane size (<n>) must be a whole number of cells` | Use a whole number of cells, or a `<n>%` string. |
| a belt's `match` file has no default export | ``belt match file <p> must `export default` a function (got <type>)`` | `export default (ctx) => boolean`. |

**Prompt-contract problems** (the lines appended to that throw) — full token list in
[prompts.md](./prompts.md):

- `<TOKEN> is only substituted when <scope hint> — as written it would reach the agent unrendered (wrap it in @@WHEN:<product>@@ … @@END@@, or use a belt where it applies)`
- `<TOKEN> is not a known prompt token — it would reach the agent literally (see docs/PROMPTS.md for the token reference)`
- `malformed clause "<full>" — a product gate is written @@WHEN:<product>@@ … @@END@@`
- `@@WHEN:<x>@@ names an unknown product "<x>" (known products: bounce_feedback, close_reference, commits, evidence, handoff, human_reply, pull_request, work_raw, work_spec)`
- `@@END@@ without a matching @@WHEN:<product>@@ before it`
- `nested @@WHEN@@ is not supported — close the previous clause with @@END@@ first`
- `a @@WHEN:<product>@@ clause is missing its closing @@END@@`

A `prompt_file_source: repo` file is **neither** existence-checked **nor** contract-validated at load —
it fails at dispatch instead.

## 7. Strictness map

| block | unknown keys |
|---|---|
| **top level** | **silently dropped** |
| **`repo`** | **silently dropped** |
| **`limits`** | **silently dropped** |
| **`local_markdown`** | **silently dropped** |
| everything else — the `work_sources[i]` object itself, `jira`, `github_issues`, `github_issues.close_on`, `sentry`, each `belt`, each step, each `effects[]` entry, `pr`, each layout / tab / pane / `setup`, each `layout_matching` rule, `conventions`, `branch`, `agent`, each `evidence` publisher variant | **rejected** — `Unrecognized key: "<k>"` at the block's path |

Why it matters: a misspelled **top-level block** (`limit:`, `work_source:`, `belts:`, `layout:`,
`convention:`) is silently ignored and the defaults apply — no error, and the generated JSON Schema
sets no top-level `additionalProperties`, so the editor won't flag it either. If a setting appears to
have no effect, **check the spelling of its top-level key first**.

## 8. Traps

1. **`belt:` is singular but holds an array.** `work_sources:` is plural. `layouts:` is plural.
   A `belts:` key is silently ignored (see §7), so you get the *missing-block* error — ``add a `belt`
   list — at least one belt pairing a source with an ordered `steps` pipeline`` — pointing at a block
   you thought you had written.
2. **`jira.status.review`, not `in_review`.** Writing `in_review:` parses fine but silently creates a
   *custom* status key while the canonical review mapping stays `"In Review"` — Jira transitions never
   change. **`github_issues.state_labels.in_review`, not `review`** — the opposite key, in the opposite
   source. Copying one to the other is a silent no-op.
3. **`github_issues.type_labels` replaces the whole default map**, it does not merge. Setting
   `{ story: Feature }` loses `bug`/`chore`/`enhancement`. Re-list every mapping you want.
4. **An `evidence` step with no `tab`+`pane` is silently skipped at load** — no error; the belt just
   becomes work→review→pr. That is the evidence opt-in. Corollary: a belt whose only step is a bare
   `{ type: evidence }` passes validation and resolves to **zero** steps (`min(1)` applies to the
   written list, not the kept list) — don't do it.
5. **`prompt_file` is validated only for `prompt_file_source: config`.** A `repo`-sourced path is not
   checked at load and fails at dispatch, mid-run.
6. **Pane `size: "150%"` passes zod and throws afterwards** — a schema-clean config can still fail to
   load. So can a missing `match`/`prompt_file`. And because those throws abort on the first failure,
   a broken config may need several `doctor` runs to surface everything, while zod issues all arrive at
   once.
7. **`active: "false"` is rejected** even though every *numeric* field accepts a quoted value. Booleans
   are strict; numbers coerce.
8. **`~` expands in exactly two places** — `repo.path` and `local_markdown.folder`. In `match` /
   `prompt_file` a `~/…` is joined onto `<repoDir>` and fails the load
   (`… not found: <repoDir>/~/…`); in `conventions.commits` it is joined too, but a path that doesn't
   stat is silently used as literal prompt text (no error). Layout pane `command`s go verbatim to
   `herdr pane run`, so the pane's shell expands `~`; `evidence.command` is exec'd with no shell, so a
   leading `~` stays literal and the exec fails.
9. **`belt[].label` has no default**, is required for `jira`/`github_issues` and forbidden for
   `local_markdown`/`sentry`. The rule is driven by the source descriptor, not a hardcoded list.
10. **Step `name` defaults to `type`**, so two unnamed `custom` steps (or two unnamed `work` steps)
    collide with "duplicate step name".
11. **The step→pane checks only run against `default_layout`** — including the first-step rule: on a
    `default_layout` belt the first *surviving* step must carry `tab`+`pane`, because an untargeted step
    spawns a dedicated pane, that new tab makes the out-of-process layout hook decline the build as "not
    a fresh 1-tab/1-pane workspace", and every later targeted step then parks `layout_wait_timeout`
    blaming herdr. `layout_matching` layouts and belts with no `default_layout` are exempt by design — a
    wrong `tab`/`pane` there fails at runtime (`layout_wait_timeout`), not at load. So that lost-layout
    failure is **impossible on a `default_layout` belt** (#10d rejects it at save/reload) and
    survives only where the factory can't see the shape coming: a belt whose layout comes *only* from a
    `layout_matching` rule, plus hand-built and multi-plugin worktrees. There it is silent — the decline
    reaches no event and no repo log, only `herdr plugin log list --plugin herdr-factory`
    ([layouts.md](./layouts.md)). **Untitled** tabs/panes are unaddressable.
12. **`read_only` + (`produces: [commits]` or `heartbeat: true`) is rejected.** `heartbeat: true`
    implies producing commits; `produces: [commits]` alone does **not** turn on the heartbeat guard.
13. **`consumes`/`produces`/`read_only`/`bounce` are `custom`-only**, and their only legal product is
    `commits` — `produces: [pull_request]` fails at parse.
14. **A `pr:` block on a belt with no `pr` step is an error, not a no-op.**
15. **An effect `on: enter` validates against every *written* step name — including a skipped
    `evidence` step.** Such an effect loads cleanly and then never fires. `on: produce` validates
    against the **kept** steps' products.
16. **A belt `effects` entry replaces the engine default for that trigger**, and effects are
    forward-only: a target ranking below the highest already enqueued is a logged no-op, not an error.
17. **A custom effect status needs BOTH an `anchor` AND a declaration** in the source's
    `status.<key>` / `state_labels.<key>` map — and is rejected outright on `local_markdown`/`sentry`.
18. **`jira.board` is required** (no default) and a numeric YAML value is coerced to a string.
    **`jira.base_url`/`sentry.base_url` need a scheme** — a bare `acme.atlassian.net` is rejected.
19. **`github_issues.repo` may be omitted**, but if neither it nor `repo.github` nor a git origin
    resolves, the failure surfaces at **source build time** (server startup), not at config load:
    `work source "<name>": no GitHub repo to poll — set github_issues.repo (owner/name), or repo.github / a git origin so the default resolves`.
20. **Zeros are legal and meaningful**: `limits.max_bounces: 0` (the first bounce escalates),
    `limits.max_capture_attempts: 0` (capture effectively disabled), `pr.automated_round_minutes: 0`
    (skip the CI/bot round). `belt.priority` also accepts negatives.
21. **`guidelines-prompt.md` is not a config key.** Its mere presence in `<repoDir>` appends it to
    every step prompt of every belt — a stray file changes every prompt in the repo.
22. **`layout_matching[].title` is documentation only** — accepted, then discarded. Don't expect it
    anywhere.
23. **`panes[].ratio` is legacy** (the fraction the *previous* pane keeps) and mutually exclusive with
    `size`. Write `size`.
24. **`agent` does not field-merge.** Setting `command` in a belt block wipes the repo-level `flags`.
25. **A poll interval at or below `limits.tick_interval_seconds` does nothing** — the tick is the floor.
26. **`config.schema.json` sits two levels up** from `repos/<name>/config.yml`; that is why the modeline
    is `../../config.schema.json`. Regenerate it with `herdr-factory schema` after upgrading.
